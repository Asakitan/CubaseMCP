# Native project probe (diagnostic only)

This one-shot DLL is diagnostic scaffolding, not an MCP backend. It is built for the installed Windows x64 Cubase 16.0.5 profile only. Loading a DLL into Cubase is a separate invasive action and is not performed by the build script. The fixed, explicitly approved loader is documented in `docs/native-probe-loader.md`.

`StartProbe` is an exported `DWORD WINAPI StartProbe(void*)` entry; `DllMain` only records the DLL handle. One invocation pins the DLL for the process lifetime and starts one worker. The worker checks the executable name and version, PE machine and timestamp `0x6adf121b`, image bounds, and the container and project-host vtables before querying the fixed observed IID through the container. It releases the returned reference only when the returned pointer equals the expected host. It then checks the dispatcher holder at `0x5890930` and, if non-null, submits exactly `{"payload_version":"2026.10.01","command":"GetMusicalTrack","type":"Tempo"}` once.

The callback vtable is a deliberately limited C-style thunk for observed direct calls, not a claim of the complete vendor ABI. Unknown interface queries return no-interface. Atomic references keep its event and storage alive after worker timeout if the host retains the callback. Response bytes are synchronously copied while borrowed, at most 1 MiB, and protected against invalid addresses. A manual-reset event waits up to 20 seconds **after the request call returns**; the request call itself has no demonstrated bounded duration. Request and callback IDs must match before response text is emitted. Callback thread ID and immediate return are recorded; the immediate return alone is not success.

The dispatcher non-null check is only a snapshot: concurrent changes could still cause the host to take its inline path. Its dispatch target, thread affinity, shutdown synchronization, nominal callback IID and full ABI remain unverified; see `docs/project-host-abi.md`. The check is not a guarantee of main-thread execution or process safety. No automatic retry occurs. The DLL is pinned because host callbacks may arrive after timeout; the loader must not attempt to unload it.

The result is written to `result-<PID>.json` next to the DLL through a new temporary file and non-replacing atomic rename. Existing results are not overwritten. JSON includes process ID, verified executable name or null, profile match, stage, query result, host match, request submission, immediate return, request and callback IDs, and callback thread ID. `responseText` appears only for a correlated copied response. `StartProbe` returns 0 when the worker was launched, 1 if pinning or worker creation failed, and 2 for a repeated invocation; 0 is not project success. Subsequent host and timeout outcomes are available only in the result file.

Build with `powershell -NoProfile -ExecutionPolicy Bypass -File scripts/Build-NativeProbe.ps1`. It invokes the installed Visual Studio 2022 x64 environment, runs a syntax-only check before one DLL build, and places the output under `artifacts/native-probe`. In isolated PID 66528 the request-capable revision acquired the host, submitted the fixed query and received a correlated `host_error_callback`; it did not return project data. Evidence: `artifacts/native-probe/loader-66528.json` and `result-66528.json`. A compile or submission does not prove the complete native ABI or host behavior.
