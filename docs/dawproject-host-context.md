## Resource destination boundaries

The filter service builds a `DPPackageManagerClient` mapping package resource kinds to host-derived base directories joined with `/Audio`, `/Video`, `/Preset`, and `/Midi`. Package method `0x41b10` calls its client for a destination per item. As shown in `dawproject-package-client.md`, it can invoke `FNFileSystem` directory creation before the host-project import begins. The current evidence identifies the source of these destination strings and one directory-creation side effect; it does not establish canonical path containment, collision/overwrite policy, archive entry traversal validation, rollback or full media extraction behavior. No assumption that all resources remain within a chosen project directory is warranted without inspecting those branches.

The import service calls the package and project-import implementations synchronously on its invoking path. No host-owned main-thread dispatcher or thread-affinity guarantee has been recovered. The live check above is diagnostic only; it does not authorize invoking or modifying an import. Further work should establish host attachment, exact resource normalization and collision semantics, cancellation, and actual thread routing before a disposable-project experiment.
