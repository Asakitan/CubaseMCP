# Read-only project candidate and root provenance

These diagnostics target only the installed Cubase AI 16.0.5 x64 profile with PE timestamp `0x6adf121b` and preferred image base `0x140000000`. They are research tools, not an MCP backend or a project operation.

`scripts/Read-ProjectCandidates.ps1` validates the isolated launch receipt, PID, process start, executable path and version, PE profile, image base and private-desktop window ownership. With read-only process access it checks fixed vtables, bounds the window-list walk, rejects cycles, reads bounded path fields, and re-reads every captured value before reporting a snapshot. Unknown window types are counted rather than interpreted. Narrow strings are accepted only when ASCII; wide strings are strictly decoded as UTF-16. It emits a uniquely named JSON report under `artifacts/ipc/` and calls no Cubase method. Repeated reads are unlocked and non-atomic; they do not prove object lifetime or exclude changes between reads.

The inspected chain is the window manager's linked list, a matching `UDocWindow`, its time controller and `MEditContext`, and a candidate `PArrangement` with an `FNPath`. The diagnostic also compares the candidate's `+0x108` pointer with the global `MProject` root at `+0xf8`. The fixed-profile `scripts/project-candidate-provenance-inspect.py` checks the relevant RTTI and vtables, and verifies that the `PArrangement` constructor calls the `MRoot` constructor and stores that result at `+0x108`. It also prints the separately traced application document-selector instructions. This static construction evidence explains the field's type; it does not prove that the unlocked candidate is the selected document.
