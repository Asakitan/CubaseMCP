# Project activation route: static selector call sites

Scope: read-only analysis of the installed Cubase AI 16.0.5 x64 PE (timestamp `0x6adf121b`, image base `0x140000000`). No process, UI, native method, project file, or license state was modified. These addresses are build-specific evidence, not an external API or a proposal to call them.

A scan of executable-section bytes for direct relative calls to root selector `0x279e640`, matched against PE exception ranges, found candidates at `0x1a323ae`, `0x1a798b2`, `0x1d144fe`, `0x1d1e207`, `0x1d39d06`, `0x1d43957` and `0x1d50979`. The scan is not a complete call graph: indirect calls and tail calls are outside it. The inspector below disassembles four candidates from established instruction boundaries; a follow-up verified all seven instruction boundaries and traced the `ActivateProject`-shaped branch in `midi-project-event-sources.md`. The existing-project open site `0x1d43957` is documented in `midi-project-notifications.md`.

* At `0x1d50920`, the routine allocates `0x2d8`, constructs through `0x1cf3e30`, optionally sets a flag at object `+0x140`, and passes its `+0x108` pointer as selector argument at `0x1d50979`. A later call to `0x279d660` receives the same pointer and `r8b=1`. The caller, object identity, side effects and thread are unresolved; allocation alone does not establish a public project-creation contract.
* The fragment beginning `0x1d1449c` resolves an object through `0x2dcc9b0`, checks non-null, compares it to the result of `0x19145a0`, and calls the selector only if the results differ. The parent event source and thread remain unknown. This is a promising normal re-selection lead, not evidence of a usable background action.
* In `0x1d39930`, a state-dependent successful path derives `r13` from a constructed object's `+0x108`, brackets selector call `0x1d39d06` with calls to a separate global object's virtual slot `+0x30` using `1` then `0`. Earlier calls and branches mean this is not a standalone operation. Their meanings and file effects are unproven.
* `0x1a797c0` derives a candidate from its receiver `+0x108`; after earlier object and vtable operations, a conditional path calls selector with that candidate at `0x1a798b2`. Its initiating event, receiver lifetime and execution context are unknown.

As previously documented, `0x279e640` returns early when its incoming pointer equals the stored current root. The presence of additional callers does not demonstrate that reselecting the current project fires a notification, that switching projects is prompt-free, or that a project can be opened in the private desktop. No supported IPC or host-main-thread dispatch contract is established by these static paths. Next, trace the parent and incoming references of the `0x1d1449c` fragment using PE unwind metadata and verified instruction boundaries, and identify the ordinary event and host thread before considering a controlled experiment. Preserve the distinction between a static candidate and a live observed transition.
