# First-project open 27: admission primitive

`/scripts/FirstOpen27Admission.psm1` adds an exclusive-create, flushed per-target-lifetime admission record. A new run ID cannot bypass an existing record for the same PID and creation FILETIME. A failed or partial write remains consumed. The caller must hold and validate target and holder handles, the restricted Job, fixture, observer and preflight before calling it; the primitive itself does not establish ownership or authorize a module load.

This is only one component. A generated launch-to-first-open source path adapts the fixed session 24 loader, observer, preflight and native module for an owned new lifetime; session 26 source drafts remain deliberately non-buildable. A host entry is submission only, not proof of completed project opening or persistence. Path and process checks are non-atomic, and this implementation does not claim resistance to a malicious same-user process.

The initial implementation was reviewed before the isolated transitions described below.

## Generated fixed-path operation

`/scripts/Invoke-FirstOpen27.ps1 -ConfirmFirstOpen27` is a single-purpose orchestration path. It rejects an existing Cubase process, launches the established no-project private-desktop holder, checks the returned holder/target creation times and target parent/command line, generates session 24 sources with the new identities and one of the two fixed fixtures selected by `-Fixture default|jump`, builds the fixed DLL, waits for read-only startup readiness, starts the separate observer, consumes the session 27 target-lifetime ledger, and invokes the adapted session 24 wrapper. The wrapper performs its existing observer, fresh preflight and live Job checks. It submits only the fixed first-project diagnostic; a successful entry return is not proof that the project opened or was saved.

The generated native module was compiled and used for two distinct owned fresh-process submissions below. The adaptation retains build-specific profile checks and fixed source text/output contracts. Process, file, desktop, Job and observer observations are sequential and non-atomic; polling may miss brief events and pathname resolution retains a race. The fixed same-user local threat model does not defend against a hostile same-user process. No automatic retries occur, and an admission consumed before an unsuccessful wrapper call remains consumed.

The PowerShell parser accepted the orchestrator and admission module. Native compilation and observed live results are recorded separately below.

Template marker counts are checked per source and substitutions use one pass. The previous canonical receipt is backed up when the new receipt is atomically published. After a successful wrapper return, the orchestrator waits up to 30 seconds for the one asynchronous result record without reissuing the host call; that record is separate from project-open completion.

`scripts/Restart-FirstOpen27.ps1 -ConfirmOwnedRestart` transitions from the owned empty-launch receipt's target and holder. It checks their exact lifetimes, parent and restricted Job, the private desktop, production port-host lifetime and exact MIDI-port availability. It byte-compares the selected fixed fixture, backs up the installed controller, owned test fixtures and canonical receipt, then consumes a lifetime-keyed restart record before terminating the old holder once. After the Job's target exit is observed, it preserves the old zero-byte startup marker in the same backup, installs the current built controller and starts `Invoke-FirstOpen27.ps1` in a hidden process. An unfinished worker is reported by PID and creation time, not restarted. Checks and file operations are sequential; a failure can leave the old instance ended or the new controller partly installed, and the backup and admission are retained. Ending that isolated instance discards its unsaved test changes, as the user approved.

The first session 27 transition ended the old owned PID 72128 and launched PID 63660, but its fresh preflight returned `informer vtable mismatch` before the generated loader or a host call was entered. The per-lifetime admission for PID 63660 remains consumed; its outcome is not retried. A later read-only startup sample observed the expected informer, listener, absent root and empty tree. The orchestrator now polls the read-only empty-project preflight before consuming a future target's admission; it still performs the wrapper's separate fresh check immediately before entry. The first restart wrapper also reported a null worker exit code despite the worker exiting with an error; it now retains a process handle and queries the native exit code. These are fixes for observed failures, not proof of a later successful run.

After those fixes, a distinct PID 28428 submitted one first-open request for `Binding26Default.cpr`, with `openStarted=true`, `openReturned=true` and `openResult=0`. A later read-only sample observed a same-name project window, root, one informer-tree entry and membership (`artifacts/ipc/midi-startup-timeline-28428-dbf5c059f7904551ae8896d745205758.json`). Those observations restored a working mapping for that lifetime; they do not prove file persistence or general project creation.

A later distinct PID 69032 submitted one first-open request for `Binding26Jump.cpr`, again with `openResult=0` (`artifacts/first-project-open-27-165f4b65f59f4aff855f17b6bedc447f/open-result-69032.json`).
