# MIDI plug-in parameter banks: 3.7

This change adds selected-track instrument parameter controls and bank-channel instrument and channel-strip parameter controls. Each group exposes parameters 0–7 and previous, next, and reset bank actions. Actions accept only value 1. For constructed bank slots, a missing host branch, value, or action is reported as `API_UNAVAILABLE`; an entirely absent mixer-bank root does not register bank-channel keys. No replacement route is used.

`controls.get` exposes a full, untruncated copy of the latest `pluginIdentity` for the individual control; group metadata in `controls.list` is a truncated summary and must not be used as the precise identity source. Writes require `expectedPluginIdentity` containing the exact observed `name`, `vendor`, `version`, and `formatVersion`, with a nonempty observed name. The selected-track controls also require `expectedTrackUniqueId`; bank-channel controls retain the existing `expectedChannelUniqueId` and session guards. Missing confirmation is `CONFIRMATION_REQUIRED`, missing valid identity is `PLUGIN_UNOBSERVED`, and an identity mismatch is `PLUGIN_CHANGED`. Existing insert and on/bypass protocols are unchanged.

Identity callbacks are accepted only for the active device and mapping and carry the observed track or channel unique and runtime IDs. A malformed identity callback from the active device and mapping clears that group's identity and feedback; callbacks from another device or mapping are ignored. Track changes, bank-slot changes, mapping deactivation, and parameter-bank navigation invalidate the applicable observations. Navigation clears the group's identity and feedback before submission; a fresh callback is required before another write.

Callback attribution and channel identity reads are not atomic. Distinct plug-in instances can share all four identity fields, so these checks do not prove instance identity. A `submitted` receipt is not evidence of completed host mutation.
