The diagnostic is fixed to those exact process creation FILETIMEs, executable build, desktop, owned fixture and one entry point. Its wrapper consumes a CreateNew admission, requires a fresh `Read-FirstProjectState24.ps1` snapshot, audits the holder's matching Job and exact flags, and checks an independently running desktop observer. The pinned diagnostic and retained path object have process lifetime, and admission/timeout or an unknown outcome is not a reason to replay. This is not wired into MCP as a second backend.
