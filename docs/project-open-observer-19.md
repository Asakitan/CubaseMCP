# Passive project-open observer 19

`scripts/Observe-ProjectOpen19.ps1` is a bounded, read-only sampler for the specific previously recorded PID 50568 and start time only. It checks the launch receipt's reported job flags, executable path and version, image base, PE signature, machine and timestamp, plus target-owned windows on `CubaseAI_MCP`; it does not independently query the live job object. It does not invoke host methods, send input, switch desktops, inject code, or operate on other processes. Receipt contents are not cryptographic proof of ownership; PID/start checks guard against reuse, not malicious tampering.

Run in a separate process with `-DurationSeconds` (5–120, default 30), `-IntervalMs` (100–1000, default 200) and, when coordinating a test, a unique 32-character lowercase hexadecimal `-RunId`. It writes a unique ready JSON via a flushed temporary file and same-directory rename only after identity checks and a first successful sample whose input desktop is not `CubaseAI_MCP`. The ready receipt gives that baseline, observer process identity and the unique result path. A later sample of the target desktop as input sets `backgroundViolation`. The duration starts before ready publication, so consumers must inspect its timestamp and allow for remaining observation time. The final JSON is created without overwrite, including partial samples and an error on ordinary exceptions; abrupt termination can leave no result. Each sample timestamps the input desktop name, foreground HWND and PID, and enumerated private desktop target windows. Handles opened by the existing native helper are closed on each sample; there is no persistent hook or retained process handle. The process start is rechecked during sampling.

This implementation uses polling rather than a WinEvent hook. It has no event coverage between samples, can miss brief desktop switches and windows, and scheduling or slow enumeration increases gaps. `GetForegroundWindow` is the caller's desktop view and must not be interpreted as a complete global foreground history across desktops. Input desktop, foreground, enumeration and timestamp are sequential, not atomic. Private windows can disappear during enumeration; absence of a prompt is not proof that none existed. The separate `Read-ProjectCandidates.ps1` can be run once before and once after a test, preserving its unique reports; its unlocked candidate snapshots do not prove project operation completion or persistence. The sampler performs neither snapshot itself.

One 5-second read-only smoke captured 23 samples with `Default` input desktop and 15 target-owned private windows. During the subsequent one-shot open diagnostic, 546 samples recorded no target input desktop or target foreground PID, while 521 included the visible private `Cubase AI` dialog. Those samples are bounded observations, not an exhaustive event history (`project-open-probe-19.md`). The separate `ProjectOpenJobAudit19` read/query-handle audit verified one matching restricted job immediately before the submission; that audit does not turn the observer's receipt check into a continuous job guarantee.
