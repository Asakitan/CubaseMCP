# DAWproject Filter: Host and Import Contract

Static read-only analysis of `C:\Program Files\Steinberg\Cubase 16\Components\Filters\dawproject.dll`, PE timestamp `0x69e0f9bd`, installed version observed separately as `1.1.0.3`. RVAs are specific to this binary, not stable SDK declarations. The live module snapshot `artifacts/ipc/dawproject-modules-3720.json` establishes that the module was loaded in isolated PID 3720 at that instant; it does not show that import ran. No import or package method was invoked; an independent factory metadata query is described below.

Steinberg's [DAWproject compatibility documentation](https://www.steinberg.help/r/cubasis/3.8/en/cubasis/topics/dawproject_c.html) lists Cubase 15 editions including AI and newer versions. The [DAWproject specification](https://github.com/bitwig/dawproject/blob/main/README.md) describes a ZIP container with XML project data. These sources establish the exchange format and published compatibility, not a background import contract for this installed instance. Steinberg's [import documentation](https://www.steinberg.help/api/khub/documents/T5ttKObCpFWiKd6dZ6c9fw/content) describes interactive folder and file selection, so it cannot by itself establish the requested unattended operation.

An independent process loaded this exact filter and queried only standard factory metadata using `FactoryProbe.Inspect`; `artifacts/ipc/dawproject-factory-independent-20261110.json` records vendor `Steinberg Media Technologies`, `ClassCount=0`, no error and no business object created. This independent factory count does not establish whether the running host registered the filter internally or whether the edition exposes an import path. It is not evidence of project creation, import, editing or saving.

## Service and selected-file path

`Steinberg::DPService` has secondary vtable RVA `0xfee10`, complete-object offset `+0x10`; byte offset `+0x38` is `0x1c7c0`. At entry `RCX` is this secondary interface, and a null `R8` returns `1` immediately. The method loads its host interface from secondary `this+0x08`, constructs text `Select DAWproject File`, and calls `0x1d560` at `0x1c91a` with the host and selection-related strings, including `dawproject`. The selected string is returned through a local string object; an empty string exits. The service accesses `lastImportPath` through host-provided objects, so this is not a read-only metadata entry. The chosen path is not a direct argument proved to be accepted by slot `+0x38`; the observed entry uses a host-dependent selection routine.

The selection helper `0x1d560` obtains host interfaces through host slot `+0x18`, then calls their virtual methods using title and filter values. Its concrete interface identities, UI behavior and threading are not fully recovered. The selection call must not be assumed windowless or replaced with a fabricated host result.

## Package and project import sequence

Export `CreatePackageManager` at `0x1af50` allocates `0x18` bytes, constructs a `Steinberg::DPPackageManager`, and returns its secondary interface at complete-object offset `+0x10`. Its secondary vtable is `0x105210`; slot `+0x18` points to `0x41b10`, and its query thunk delegates to `0x42830`, which recognizes IID raw bytes `96 8b 2e 8d c3 68 1b 4c bd ca 97 e1 9c d2 38 99` at `0x15a840`. The service constructs a manager locally via `0x41720` with `RCX=RBP+0x30`, then directly calls `0x41b10` at `0x1cb76` with `RCX=RBP+0x40`, the secondary interface at complete-object `+0x10`; `RDX` holds the selected string's character data and `R8` a local structure. An earlier revision incorrectly described this `RCX` as the complete object. The callee checks both latter arguments for null and uses the path in `0x8f0e0`/`0x8f870`; the latter scans 16-bit code units. It references `/project.xml` at `0x41caa`, processes other paths and filesystem objects, and returns a pointer in `RAX` or null. The third argument's observed origin is described below; the complete ownership, failure and side-effect contract is not recovered, so package parsing must not be treated as a pure function based on the name or export alone.

The third argument has a more specific observed origin. The service constructs a `DPPackageManagerClient` at local `RBP-0x10` using `0x42e40`; its secondary interface is at complete-object `+0x10`, i.e. `RBP`, which is passed as `R8` at `0x1cb76`. The RTTI-identified secondary vtable is `0x105640`. Before the call, the service invokes `0x42f40` to associate integer tags `2`, `4`, `1`, and `3` with a host-derived base path plus `/Audio`, `/Video`, `/Preset`, and `/Midi`, respectively. The manager calls this client through vtable slot `+0x18` at `0x41f17`; target `0x43050` looks up the tag and returns a path-derived string or null. These data movements support a client-provided media-destination role, but do not establish complete interface ownership, path normalization, extraction effects or a safe callable contract.

On non-null package result, the service wraps the pointer with `0x1b2c0`, then calls a virtual slot `+0x18` on it at `0x1cb9e`; the returned non-null object becomes `RDX` in the direct call to `0x1f710` at `0x1cbc8`. `RCX` is a stack-constructed `DPHostProject` from `0x1e000`. The call is made synchronously by this observed service path; no main-thread transfer is established.

`DPHostProject` constructor `0x1e000` retains its input host at complete-object `+0x68` via host slot `+0x08`. It asks that host's slot `+0x18` for raw IID `13 28 7c 3d bf 8a ae 4a a2 3a 11 bf 37 21 4c 36` at `0x15a510`, calls slot `+0x28` on the returned interface if present, and retains the resulting interface at `+0x70`. At `0x1f77a` and `0x1f805`–`0x1f818`, the importer requires non-null host-project/context interfaces and exits when those prerequisites are missing. The import implementation references `Import DAWproject`, `Import Transport`, `Import Track`, and `Import Tracks`, and makes numerous host virtual calls. This is a project-modifying operation, not a no-op parser or evidence that a new Cubase project was created.

## Boundary and next evidence

The observed selection, package preparation and mutation are separate stages, but their callable parameter types, allocations, output ownership, project lifecycle and main-thread contract are incomplete. Presence of the loaded component does not establish a no-dialog import interface, support for all DAWproject data, or project save/create support. A discriminating static next step is to recover the returned-object interfaces and extraction side effects, plus the host IID's concrete implementations and threading, before considering a copied-project import. Do not call the importer or manufacture host context while these contracts are unresolved.
