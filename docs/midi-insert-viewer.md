# Selected-channel insert viewer

The installed Cubase 16 MIDI Remote v1 declarations define `makeInsertEffectViewer`, `includeEmptySlotsOnly`, `excludeEmptySlots`, `accessSlotAtIndex`, viewer actions, plug-in identity callbacks and parameter-bank values/actions. The [Steinberg API reference](https://steinbergmedia.github.io/midiremote_api_doc/codedoc_api_reference/) lists these members but does not establish their live behavior for every edition or project.

The controller creates independent fixed-named viewers for `track.insert.all`, `.empty`, `.occupied` and `.slot.N`. The empty and occupied viewers call the corresponding declared filter; slot viewers pass `N` to `accessSlotAtIndex`. The number of indexed viewers comes from `getNumberOfInsertEffectSlots`; a maximum over 16 reports `HOST_LIMIT_EXCEEDED` and creates no indexed viewers. A failed creation or filter is recorded as unavailable. An index is a filter argument, not an independently verified current slot or plug-in identity. Viewers and filtered targets can change with host state or actions.

Each available viewer exposes read-only on, bypass, automation and eight parameter-bank bindings. Viewer previous/next/reset and bank previous/next/reset are fixed action controls requiring value 1 and an explicit `expectedTrackUniqueId`; the existing session guard applies. Their receipt means only that a binding pulse was submitted. Changes clear cached selected-track observations and callback identities. The current selected-track identity is checked at submission, but identity is not an atomic guarantee of a particular plug-in, viewer target or parameter. Parameter and plug-in on/bypass/automation writes are deliberately not exposed because the declaration alone does not prove safe target attribution.

The identity callback is recorded only for the active device/mapping and is tagged with the selected track observed when the callback executes. Track changes and mapping deactivation clear it. This does not prove callback provenance across a track switch. Viewer controls are discoverable through paginated `controls.list` and individual `controls.get`; incomplete pages must be followed. The `mEdit` value and `followPluginWindowInFocus` filter are intentionally omitted. There is no GUI operation, alternative backend or retry.

The focused `node --test tests/remote.test.cjs` run passed 44/44 using the real controller with an API-shaped fixture. A subsequent regression also demonstrated that a missing filtered action binding previously produced a false submitted receipt; the controller now reports `API_UNAVAILABLE` for that condition. The later full Node suite passed 70/70. Coverage 3.2 construction was logged in PID 45628 and coverage 3.3 construction in PID 3720, but no mapping activation or live control response was observed. Host/edition availability, exact slot semantics, navigation effects and callback timing remain unverified.

## Mixer-bank insert viewers

Each of the eight fixed bank channels gets separate all, empty and occupied viewers plus indexed viewers when the declared insert-slot maximum is at most 16. Larger maxima mark indexed groups `HOST_LIMIT_EXCEEDED` without partial indexed admission. Missing host branches and filters report `API_UNAVAILABLE`. Viewer on, bypass, automation and eight parameter values are read-only: channel identity alone does not identify an insert slot, plug-in or parameter. `mEdit` and window-focus controls remain absent.

Viewer and parameter-bank navigation are momentary actions guarded by the observed `expectedChannelUniqueId` and the session. Before submission they invalidate that channel's admission, values and plug-in identities. Plug-in identity callbacks are tagged with the channel identity visible at callback time and clear that viewer's values; observed bank-slot identity changes and mapping changes clear cached identities. These callbacks and read-only feedback still do not prove their originating plug-in after a delayed event, and navigation submission does not prove its target or completion. Fixture tests exercise guards, missing branches, slot bounds, identity changes and stale sessions. The isolated PID 39068 logged construction of 3.5, but no 3.5 handshake or viewer operation was observed.
