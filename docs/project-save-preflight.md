# Project Save Preflight Alert Path

Target: installed Cubase AI 16.0.5 Windows x64 executable, timestamp `0x6adf121b`. This is bounded static disassembly, not an SDK contract or evidence that a save was attempted. No process, UI, memory, license state or project file was accessed. See `project-save-target.md` for the separate post-error alert, deletion and transformed-path uncertainties.

In arrangement save `0x1d579d0`, the working `FNPath` copy is constructed at `0x1d57fa5`–`0x1d57fc8` from the incoming path; virtual slots `+0xf0`, `+0xf8` and `+0xe8` then process it. At `0x1d58047` the function calls `0x3ac5800` and tests its byte result. If zero, execution branches to `0x1d581a2`, bypassing the alert sequence. If nonzero, execution derives a string from the working path, obtains an indirect receiver via `0x3ad6050` at `0x1d580a1`, constructs a request/result-shaped object and invokes the receiver's first virtual slot at `0x1d5813b`. The previous static recovery in `project-save-target.md` identifies `0x3ad6050` as an alert-service getter whose default factory requests `Alert::IDialog`.

After this indirect call, the bounded branch releases local objects and falls through to the common continuation at `0x1d581a2`; this slice does not show a direct test of the returned result before that continuation. The later save flow can reach file-open site `0x1d583c2`, though intermediate conditions are not exhaustively traced. Thus an alert-service invocation is possible **before** the identified file-open site as well as on a later save-error path. This does not establish the predicate's meaning, effective provider, visible dialog, user response, successful file creation, or whether a given save reaches file-open. An existing document path and a bypassed initial path picker are insufficient to establish a prompt-free contract.

Reproduce with `E:\Py\python.exe scripts/project-save-preflight-inspect.py`. The inspector checks x64 machine, PE timestamp, image base and the PE runtime-function start, then decodes from that start before filtering to the relevant fixed file-backed ranges; the profile is build-specific. Remaining work is to trace the predicate and both path branches, the indirect provider's thread and completion behavior, and the actual file replacement and error result. No `CreateNew`, `Open` or `Save` implementation is claimed.

## Shared startup-state byte

Static leaf `0x3ac5800` reads the byte at image RVA `0x599df29`. Leaf `0x3ac6030` sets that byte to `1`; decoded caller `0x3abe630` first checks the getter, returns on nonzero, and otherwise calls the setter at `0x3abe651` before constructing another path-shaped object. Separately, startup-marker routine `0x3ac5c70` checks this same byte and, if it is zero, constructs the known `ApplicationStarted.txt` path and conditionally invokes filesystem-like slots. This connects the save preflight gate to a broader host state shared with marker handling, but does not establish the byte's meaning, why or when the setter's caller runs, whether an alert is displayed, or whether save is prompt-free. Neither changing the flag nor calling the setter is justified by this observation.

`E:\Py\python.exe scripts/project-save-preflight-state-inspect.py` validates the fixed PE profile, both complete leaf instruction bytes and their common target, and decodes the caller and marker routine from PE runtime-function starts. The normal create path, thread dispatch, save completion and destination/error contract remain open.

Another conditional pre-file-open alert and its original-path filesystem predicate are documented in `project-lifecycle-15.md`; avoiding this preflight alone does not establish a prompt-free save.
