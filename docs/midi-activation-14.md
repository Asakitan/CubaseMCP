# MIDI scanner identity registration follow-up

Scope: static disk-only inspection of Cubase 16.0.5 x64, PE timestamp `0x6adf121b`. No MIDI transmission, host invocation, process write or configuration change was performed.

Function `0x22b6960` obtains the global scanner at RVA `0x58f8d00`, creates the six-byte sequence `F0 7E 7F 06 01 F7`, and twice passes it with a different `F0 7E 7F 06 02 ... F7` response-shaped sequence and integer 400 to `0x22d1d60`. The request bytes correspond to Universal Device Inquiry; the response-shaped byte patterns contain `FF` bytes whose matching semantics are not established. The 400 value is not independently proven to be a timeout. The registration function checks each buffer is longer than three bytes and starts with `F0` and ends with `F7`; it updates scanner state and registers the buffers in separate collections at `+0x340` and `+0x328`. This does not establish actual transmission, a response, a target port, or what bytes populate record `+0x60`.

The existing `docs/midi-detection-correlation.md` distinguishes the scanner detail tree from the registry port tree. A registered inquiry is not evidence that identity is required for name-only detection; Steinberg's [detection documentation](https://steinbergmedia.github.io/midiremote_api_doc/api-details/detection-unit/) describes name and identity criteria separately. Neither the response format nor a connection between response absence and the observed zero-length details has been established. Do not add an identity responder based on this observation alone.

Reproduce the bounded instruction listings with `python scripts/midi-activation-14-inspect.py identity_registration` and `python scripts/midi-activation-14-inspect.py sysex_pair_registration`; the script checks the image machine, timestamp and preferred base and reads only the executable on disk. Next, trace the collection consumers and sender, and independently correlate a received response with the exact scanner record and detail vector before considering a production protocol change. Existing snapshots from PID 3720 are historical, and do not establish current-process behavior.
