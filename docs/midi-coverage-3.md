# MIDI Remote coverage revision 3

Based on the installed Cubase 16 MIDI Remote v1 declarations. The initial revision 3 slice was fixture-tested only; later revisions were installed and their construction observed, without live mapping verification.

- Control Room adds momentary `controlRoom.nextDownmix` and indexed source selectors for external inputs, target monitors, main cue sources and indexed phones cue sources. Counts are the corresponding host maxima, not assertions that channels exist. The combined selector budget is 64; a group exceeding the remaining budget is rejected without partial admission.
- A named mixer bank zone exposes five fixed momentary action controls `mixer.bank.{previous,next,left,right,reset}`. A value of exactly 1 is required; the resulting receipt means submitted, not proof that bank position changed. Channel binding, bank identity and bank configuration are not included.
- Each available selected-channel strip slot records a host identity callback under its control group and, where `mParameterBankZone` exists, creates eight bank parameter values and fixed previous/next/reset bank action controls. Action value must be 1. Track identity changes, page deactivation and bank actions invalidate selected-track observations. Identity is callback evidence associated with the selected track observed at callback time, not independently verified plug-in state or proof of the callback's provenance during a track transition.
- Exceptions fetching the selected mixer channel or transport value are captured so those specific getters do not abort controller construction. This is not proof all host getters or initialization conditions are covered.

Every operation remains bound to the active MIDI session and existing control schema. The earlier 3.3 server expected `2026-11-10-coverage-3.3`; that controller was installed and its construction was observed in PID 3720. Revision 3.4 extends bank controls as documented in `docs/midi-mixer-bank.md`; current results do not establish that Cubase AI exposes a given branch, that bank controls refer to a particular plugin parameter, or that the installed driver has an active mapping. Missing APIs report errors and no foreground or alternate backend is added.

Revision 3.1 adds bounded lifecycle messages to the Cubase script console: construction, device and mapping activation, first input, first decoded request, first idle and first response frame per mapping session. No request payload, session identifier or project content is logged. These observations diagnose a real silent timeout; they do not replace an MCP handshake or host feedback.

At the initial revision 3 slice, insert-effect viewers, mixer bank binding and channel identity admission were still open. Later revisions added fixed viewers and guarded bank positions; the current gaps include bank plugin parameter banks, configurable bank filters, per-channel meters with trustworthy channel count, and project/event/export lifecycle operations. Plugin editing windows remain outside the background-only path. No live investigation, driver installation, or host restart was performed in the initial slice.

## Compact handshake and discovery pagination

A fixture with 32 sends, 32 cue sends and 5,000-character host binding errors reproduced `RESPONSE_TOO_LARGE` on the previous aggregate `bridge.status`. The revision 3 handshake now returns session, version, revision, active state, policy, a few static feature flags, discovery directions/counts and transport queue limits. It no longer refreshes DirectAccess or embeds root objects, controls, groups, commands or transport observations. Use `objects.list`, `controls.list`, `commands.list` and `transport.get` for those details. Tempo and locator setter availability is available through `transport.get.features`; a failed capability read is reported as `featureError`. This removes a compatibility assumption for clients that previously read embedded status fields; clients that only consume session/revision remain compatible.

`controls.list` accepts independent `offset`/`limit` and `groupOffset`/`groupLimit` parameters, each limit 1–16 with default 16. The existing `controls` array and `groups` object remain, but now represent pages; follow `nextOffset` and `nextGroupOffset` independently until both are null. Ordering and cursors are valid only within the active mapping session; metadata and observations can change between pages. Previously parameterless calls remain valid but return the first pages, not the complete registry. The server validates the same bounds. Individual control and group descriptive strings are capped at 128 characters with an ellipsis; errors also carry `messageTruncated` when their original message exceeded 512 characters. Identifier and operation-key fields, including `uniqueId`, `trackUniqueId`, `currentUniqueId`, `uniqueIdString`, `uniqueName`, `pluginUid`, `session`, `root` and `key`, are preserved rather than shortened. An exceptionally long identity can still exceed the transport's maximum response size and fail explicitly instead of yielding a fabricated identifier. Session and revision guards remain unchanged. The live verifier uses `cubase_control_get` for volume rather than assuming it appears in the first list page.

The compact-handshake regression failed before the fix as described above. The session 08 Node suite passed 70/70, including long-identifier, transport-feature, missing-filtered-action and bank-slot identity regressions; session 11's revision 3.4 suite passed 74/74. Fixtures are not live-host evidence.
