# Moved-project working-directory prompt

The session 19 fixed host-open submission for a copied test CPR produced a private dialog asking whether to use the new `project-open-probe` working directory or the old `live-smoke` directory. No dialog input was sent; the open remains `unknown` (`project-open-probe-19.md`). A read-only private-desktop window capture records the displayed paths.

Static inspection of the fixed Cubase 16.0.5 image locates the matching untranslated prompt literal at RVA `0x448be80`. In the containing routine beginning at `0x2810150`, the call at `0x28104be` compares two path-shaped objects through slot `+0x70`; a nonzero result branches around the later prompt construction. Other branches depend on a caller-supplied byte, a local mode and a separate helper. The modal provider call is conditional at `0x28108bd`–`0x28108c5`. The compared objects' complete semantics, the call path to this routine for the observed request and the other conditions remain unverified. A same-working-directory fixture is therefore a candidate for a distinct future experiment, not proof of a prompt-free open.

The application-open routine at `0x1d53bb0` stores its optional second argument but, on the ordinary existing-project branch around `0x1d53d2b`–`0x1d53d3c`, calls `0x1d42430` without directly passing that value. Another branch can pass it elsewhere. These paths do not establish that supplying `ProjectDir` would suppress the observed dialog. `scripts/project-moved-prompt-19-inspect.py` verifies the fixed PE profile, prompt literal and call bytes, then prints bounded ranges from runtime-function starts.

The 93,085-byte copied CPR contains `FNPath`-adjacent cleartext: a big-endian length 14 at `0x10056` precedes `live-smoke` and its terminator/marker at `0x1005a`; a length 30 at `0x1007e` precedes `E:\VC\CubaseMCP\artifacts\` at `0x10082`. Another path-shaped field at `0x101c9` contains the full old directory. The outer RIFF length at `0x04` equals file length minus 12; these byte observations are not a CPR format specification or proof of field semantics. No CPR byte was changed in this investigation. Any later test must preserve the unresolved outcome of the current one-shot request and independently verify content, save and reopen rather than treating an edited file or window title as project creation.

Session 20 started a different byte-identical copy from the existing `live-smoke` directory in a new process. Sampling observed a matching project title and no exact `Cubase AI` dialog title, but this was a startup path, not another host-open submission; polling can miss windows and the path fields' semantics remain hypotheses. It therefore does not establish that same-directory host-open is prompt-free. The session 19 process was terminated with its dialog unoperated and its submitted outcome remains `unknown`.

The later distinct same-directory host-open submission produced a different private prompt asking whether to activate a project, observed in `artifacts/project-open-probe-20/dialog-24036.png`. It was not operated and its outcome remains unknown. This is a discriminating observation, not proof of the path-comparison semantics, the absence of every other prompt, or completed project loading (`project-open-probe-20.md`).
