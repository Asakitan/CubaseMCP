# Mixer bank channel bindings

This slice creates one named `MR_MixerBankZone` and eight fixed `makeMixerBankChannel` positions when the host exposes that API. Each position has controls `mixer.channel.N.{volume,pan,mute,solo,recordEnable,monitorEnable,automationRead,automationWrite}` and read-only aggregate meters `mixer.channel.N.meter.{level,maximum,clip,peak}`. These are declaration-backed host bindings, not generated channels; unavailable positions and values report host/API errors. Bank filtering is not changed.

Each `controls.get` or relevant page of `controls.list` queries the actual slot `getUniqueIDString` and `getRuntimeID`, reports them in `control.channel` and/or group `mixer.channel.N`, and admits that slot/identity for the session. Writes require `expectedChannelUniqueId` matching the previously exposed slot identity and the current host identity; a changed runtime ID invalidates admission even when the unique string stays the same. Missing admission, mismatch, no channel and invalid identity fields are errors, not guessed results. Discovery marks a slot unavailable and reports its error when the host supplies no identity. Other controls reject `expectedChannelUniqueId`. Meters reject writes.

Host value feedback is associated with the slot identity observed when the callback executes. A slot's cached feedback is cleared on identity or runtime ID changes, explicit bank navigation, and mapping activation/deactivation. Bank navigation clears all slot identities and admissions before submitting its fixed action, even if the host later rejects or delays it. A receipt is only submission, not proof of navigation or a changed mixer value. The next write requires a fresh explicit identity read.

These checks are not an atomic transaction with Cubase: a slot may change after an identity check, and a delayed callback may be attributed to the identity visible at callback time rather than its source. The host's `getUniqueIDString` is not claimed to be a permanent project ID. SDK declarations do not establish channel lifetime, callback causality or edition availability. No mixer window is opened or focused and no extra backend is used. Session/revision checks and no-replay rules remain unchanged.

Coverage does not include bank EQ, sends, plugin slots, bank filters, dynamic channel counts, or per-channel-index meters. This slice uses fixture tests, not live verification.
