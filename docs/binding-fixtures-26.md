# Binding experiment fixtures 26

`scripts/Prepare-BindingFixture26.ps1 -Mode default` and `-Mode jump` create only `Binding26Default.cpr` and `Binding26Jump.cpr`, respectively, under the fixed owned `artifacts/live-smoke` directory. The source is the pre-existing 93,085-byte `MCP Device Test 20261110.cpr`. The script rejects reparse-point directory components or source files, opens the source without write sharing, creates the destination exclusively, flushes it and compares every byte while both handles remain open. Existing destinations are not overwritten. A failed copy can leave a partial destination, which is evidence to inspect rather than an automatic retry target.

The copy is a disposable disk fixture, not a new Cubase project or a successful open/save. Its fixed source and names do not make later pathname resolution atomic; a future run must recheck file identity and contents at its own admission point. No UI, process, installed controller or MIDI port is changed by fixture preparation.

Both distinct fixtures were prepared in session 26 with successful bytewise comparison: `artifacts/ipc/binding26-fixture-default-f27f21953234467d8dbffc47d23d8097.json` and `artifacts/ipc/binding26-fixture-jump-f9c78510200b4376a11cc3388674a112.json`. Neither has been opened in Cubase by this experiment.

`Prepare-BindingRun26.ps1` prepares a separate, non-admitting run plan only after the existing empty-start trace has published its fixed arm record. It cross-checks the arm against the previous owned receipt and live target/holder/trace creation times, verifies exactly one matching Cubase process, and re-compares the mode-specific fixed fixture with the source while both read handles are open. It atomically publishes a CreateNew run plan and performs no launch, restart, MIDI operation or host call. The receipt and plan are not authenticated against a same-user process; a future admission still requires the actual new target/holder Job, desktop, observer and fresh preflight.
