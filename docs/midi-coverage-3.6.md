# MIDI Remote revision 3.6: selected-channel observation guards

Revision `2026-11-10-coverage-3.6` retains the single MIDI Remote backend and existing control inventory. It adds optional selected-channel runtime-ID checks to `cubase_control_set` and `cubase_track_navigate`. Read the unique ID and runtime ID from `cubase_selected_track`; `expectedTrackRuntimeId` requires `expectedTrackUniqueId` on track controls, and `expectedRuntimeId` accompanies `expectedUniqueId` on navigation. A mismatch returns `TRACK_CHANGED` before submission. Existing clients may omit the optional runtime guard. These checks are not atomic with Cubase state and do not identify a particular plug-in or parameter.

Selected-track feedback and callback identities are invalidated when either the observed unique ID or runtime ID changes, or when reading the selected-channel identity fails. A valid active-device/mapping plug-in-identity callback also clears feedback in that selected insert or channel-strip group before recording the new callback identity. Other selected-track groups are retained. Bank-insert groups already cleared their own feedback and now use the same clearing helper. Delayed feedback can still be attributed to the identity visible when the callback executes; the fix does not establish callback provenance.

The live verifier now supplies both track identifiers. It issues the distinct restore write only after the requested target value was observed, and never restores automatically after an uncertain initial write or an unobserved target. A failed or uncertain restoration is reported without a repeat. Each verification report receives a unique non-overwriting path. These policies do not prove that the original write caused the observed feedback or that any host operation persisted.
