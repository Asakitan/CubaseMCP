# Project create/save: local-volume predicate follow-up

Target: installed Cubase AI 16.0.5 x64, PE timestamp `0x6adf121b`; this is static disk evidence only, not a host invocation or a completed project operation. `project-lifecycle-15.md` records the second pre-file-open alert and its higher-level path gate.

Within `0x3b08010`, after `GetFileAttributesW` returns a valid value with bit 0 clear, the routine builds string-like objects and compares against the two UTF-16 backslashes at RVA `0x4831854`, passing length `2` and a zero fourth argument. If the comparison returns zero it returns true. Otherwise it overwrites the fourth UTF-16 code unit of its local path buffer with zero, invokes `GetDriveTypeW` with that buffer and returns false for drive types `0`, `1` or `5`, true for the other returned values. The comparison helper contains multiple character-storage branches; these observations are not a proof that an arbitrary runtime path is interpreted as a particular prefix. The higher-level `0x3b04ae0` can also return false before reaching this function, including its own path-type check. The original-path predicate does not identify the transformed output target.

A normal existing writable file on a local drive is therefore a **candidate for further observation**, not a guarantee that the full predicate succeeds or that any save is prompt-free. Read-only inspection of the owned disposable project's canonical path, attributes and volume type may help choose a future test, but it cannot prove the host's path-object transformation, eliminate concurrent changes, or predict its alert provider. The earlier preflight and error alert paths, selected output and deletion behavior, host-thread route, completion and correlation remain independent open issues.
