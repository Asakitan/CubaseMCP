# Project activation prompt: static consumer 22

## Fixed-image evidence

Cubase 16.0.5 x64 timestamp `0x6adf121b`, image base `0x140000000`. A disk-only scan of executable sections for signed RIP-relative displacements to RVA `0x58c9970` followed by Capstone linear decoding from each containing PE runtime-function start identifies two instruction references: initializer `0x1335b0f` and consumer `0x1d4385c` (function `0x1d42430`–`0x1d441cd`). At `0x1335b08` the initializer loads UTF-16 key `Do you want to activate the project?` at RVA `0x42e7510`; it passes the global address `0x58c9970` and key to `0x3a7f450`. The consumer passes that same global address to `0x3a85e80`, and feeds its returned pointer into `0x15ff9c0` on a constructed object. This is a concrete static consumer of the initialized key, not a dynamically verified display or call stack. A scan for references to `0x42e7510` found only the initializer instruction under the same method. Scans do not exclude different encodings, dynamic references, other modules, or non-linear code.

At `0x1d4384a` a local object is constructed, at `0x1d43856` its first dword is set to 1, and the translated value is attached through `0x15ff9c0`. Two other global values are retrieved via `0x3a85e80` and attached through `0x164da10` and `0x164d9d0`. `0x1d437fe` calls `0x3ad6050(0)`, saving its result in `r12`; `0x1d43808` reads its vtable and `0x1d4380b` saves slot zero in `r15`. `0x1d438b2` invokes that slot with `RCX` equal to the returned object, `RDX` pointing to a local result and `R8` equal to the built parameter object. The concrete dynamic implementation is not identified. The first dword of its returned object is saved in `ESI`; if it equals 2, `0x1d43918` sets `[rsp+0x50]` to zero and skips the `0x279e640` call at `0x1d43957`. Any other value or a skipped prompt reaches that call. This is a branch observation, not proof that value 2 means a particular button or that the call completes activation.

## Predicates and upstream provenance

The sequence `0x1d437b5`–`0x1d437f8` reaches the consumer only if all of these tests pass: original receiver `[r12+0x15] != 0`; the preexisting byte `[rsp+0x50]` (copied to AL before being set to 1) is zero; signed result of `0x279d940(global)` exceeds 1; `[rsp+0x51]` is zero; `SIL` is zero; and original receiver dword `[r12+0x10]` is zero. The function entry saves `RCX` in `r12`; later `0x1d43805` overwrites that register with the UI-service object. The `0x279d940` result has not been independently identified as a project count.

At entry `SIL` receives the low byte of `R8`; however by the prompt test it has been overwritten at `0x1d43709`/`0x1d4370e`. It is one only on a path where a virtual `+0x1d8` result fails an unidentified `0x3b158a0` test, `r13` is non-null, and `0x3b7f430(r13+0x10, "Nuendo Live", 0)` returns zero; otherwise it is zero. Separately, the immediately preceding `[rsp+0x51]` assignment is one for a zero comparison result against either `"Sequel"` or `"*Sequel*"` through the same helper, and zero otherwise; the full semantics of the helper and the `r13` object are not established. The prior `[rsp+0x50]` derives on one branch from incoming `R8B` at `0x1d4259c`, or is initialized to zero at `0x1d425a9`; earlier control flow and subsequent mutations must be considered before mapping it to a public option.

The existing-project branch at `0x1d53d2b`–`0x1d53d3c` supplies `R8=0`, `R9=0`, and fifth argument 1 to `0x1d42430`. This connects the consumer to one static application-open branch, not to an observed execution of it. The host open optional argument is not directly forwarded in this branch. Neither the receiver fields nor an exposed option that reliably enforces any skip condition has been identified. These predicates therefore do not establish an accessible noninteractive contract, and a skip of this one consumer does not exclude other dialogs.

Reproduction: load the fixed PE with `pefile`, check timestamp and base, use exception-directory function boundaries, and linearly disassemble `0x13359f0`–`0x1335bab`, `0x1d42430`–`0x1d441cd`, and `0x1d53bb0`–`0x1d53fc8` with Capstone x64. Decode from the function starts and select the RVAs above. Ghidra MCP was attempted but its localhost service refused connection; no Ghidra result is claimed. No target interaction, process writes, configuration changes, UI action, or host request occurred in this investigation. Project activation, open completion and saved state remain unknown.
